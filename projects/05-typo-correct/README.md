# 项目⑤：中文错别字纠正 —— 评测框架 + 统计基线

为 docs/nn-upgrade.md 的 P4 构想（字符级「保留/替换」编辑式模型）立靶子：
先有可复现的评测集和两个基线，将来编辑式模型一训出来就能直接上秤。

本轮**不训模型**。三个脚本：

```
data_gen.py    合成错别字数据 + 混淆表 + 评测用 CharLM（全部产物落 data/）
baseline.py    (a) 照抄不改基线  (b) CharLM 统计基线
eval.py        SIGHAN 风格指标（检测级/纠正级 P/R/F1，按同音/形近分桶）
test_eval.py   pytest：指标计算正确性（手工构造、可口算的例子）
```

复现：

```bash
PY=/Users/yingyang/.workbuddy/binaries/python/envs/default/bin/python
cd projects/05-typo-correct
$PY -m pytest test_eval.py -v                 # 指标单测（8 个全过）
$PY data_gen.py                               # 生成数据与评测 LM（~5s）
$PY baseline.py --mode copy --input data/test.jsonl --output data/out_copy.jsonl
$PY baseline.py --mode stat --input data/dev.jsonl  --output data/out_dev.jsonl  --tune
$PY baseline.py --mode stat --input data/test.jsonl --output data/out_stat.jsonl --threshold 4.0
$PY eval.py data/test.jsonl data/out_stat.jsonl
```

## 数据来源决策

任务允许联网拉 SIGHAN 等公开 CSC 数据集（最多试 2 次），**本轮未使用，全部本地合成**：

1. 仓库已有 `vendor/yue_pairs.json`（16.9 万句简体中文聊天语料）可作句子底稿，
   `data/lexicon.tsv`（19.3 万条「拼音键→词」）可作同音混淆源，两样凑起来足以合成
   同音 + 形近两类错误，且完全离线、固定种子、可复现；
2. SIGHAN 的价值是「真人真实错字分布」，将来接 P4 模型时值得联网拉一次做外部验证集，
   但它不提供句子底稿之外的额外能力，不影响本轮「立靶子」的目标；
3. 合成数据的已知偏差见下文「局限」。

### 合成策略（`data_gen.py`）

句子底稿：yue_pairs zh 侧过滤（8~40 字、≥6 个汉字），按句子 MD5 稳定划分
train 88% / dev 4% / test 8%（137k / 6.1k / 12.5k 句）。

| 错误通道 | 做法 | 占比 |
|---|---|---|
| 字级同音 | lexicon 同一拼音键下的单字互为候选（多音字取并集），词频门槛 ≥50 | ~55% |
| 词级同音 | 同一键下的 2~4 字词整词替换，逐字记录差异（共有字不算错） | ~33% |
| 形近 | 手写 62 对常见形近字（己已巳/末未/拆折/崇祟…），双向；刻意不收互为同音的对，保持桶互斥 | ~12% |

每句 70% 注 1 错、30% 注 2 错（词级替换会拆成 2 个字级错误）；评测集混入 15% 干净句
用于统计误报。混淆表规模：同音字 3901 个、形近字 82 个、可替换词 19481 个。
产物 JSONL 行：`{"sentence": 错句, "errors": [{"char", "correct", "position", "type"}]}`，
`position` 为错句下标（只替换不增删，长度不变——与 P4 的编辑假设同构）。

### 评测 LM 与污染隔离

`data/lm_char.marshal`（产品 LM）**由 yue_pairs 全量训练**，而评测句也取自 yue_pairs——
直接用它评测等于让 LM 背过答案。所以 `data_gen.py` 只用 **train 划分**现训了一个
3-gram CharLM（`data/lm_eval.marshal`，2.8MB，vocab 4348）作为默认评测 LM；
`baseline.py --lm` 仍可指向产品 LM 做对照（见结果表：纠正 F1 虚高 +4.9pt，证实污染真实存在）。

## 评测口径（`eval.py`）

- **检测级**：位置找没找对。P = 命中位置/全部预测，R = 命中位置/全部金标错误。
- **纠正级**：位置对且建议字对。P 的分母是全部预测（误报算进去）。
- 分母为 0 按 0 计（照抄基线因此为 0）。
- 分桶（homophone/shape）：桶内 R = 桶内命中/桶内金标；桶内 P = 桶内命中/(桶内命中+全局误报)
  ——预测不带类型标签，误报计入每个桶的分母（CSC 论文常用口径）。

## 实测结果（test 集 1200 句、金标错误 1485 个）

| 基线 | 检测 P/R/F1 | 纠正 P/R/F1 | 同音纠正 F1 | 形近纠正 F1 |
|---|---|---|---|---|
| (a) 照抄不改 | 0 / 0 / **0** | 0 / 0 / **0** | 0 | 0 |
| (b) CharLM 统计（阈值 4.0，dev 上调出） | 0.812 / 0.659 / **0.727** | 0.711 / 0.577 / **0.637** | 0.642 | 0.469 |
| (b') 同上但用产品 LM（污染对照，勿当成绩） | 0.882 / 0.665 / 0.758 | 0.798 / 0.601 / 0.686 | 0.690 | 0.595 |

阈值扫描（dev）：0→8.0 之间纠正 F1 单峰，4.0 最高（0.649）；阈值越低检测 P 越差、
越高 R 越差。统计基线与「照抄」的差距（0 → 0.64）就是上下文打分的全部价值；
P4 编辑式模型的靶子：**纠正级 F1 > 0.64（诚实口径）/ 0.69（见对照警示）**，
且推理预算 3~5ms/句。

## 失败模式（来自 test 集实测输出）

1. **罕见但正确的搭配被改坏**（误报主因）。干净句「学富五车，道德高尚」被判把
   「富→不」——成语/俗语在 train 划分里出现少，n-gram 分数低于常见字组合，
   阈值拦不住。粤语俗语「鸠屎」被改成「久屎」同理。
2. **形近桶高查全低查准**（R=0.82 / P=0.33）。「不至干破裂」的「干→于」漏检：
   局部三字窗口里 干/于 都通顺，形近候选一有风吹草动就被提上来，反而在
   别处制造了大量误报。形近错的消歧需要更长程的语义，正是 n-gram 的盲区。
3. **多错句只修最顺眼的一两处**。「你现回去自系位」金标 2 错（现→先、系→己），
   只修了「现→先」；「却是不搓」金标 3 错修对 2 处。逐位置独立打分没有
   「一句话最多错几个」的联合约束，错误越多漏得越多。

## 如何接 P4 编辑式模型

docs/nn-upgrade.md P4 的判断：任务本质是「77% 字符不动」，seq2seq 从零生成把八成算力
花在抄写上；改成字符级「保留/替换」标注模型，一次前向出整句，44ms → 3~5ms，
且天然只在该改的位置动手。本框架为它准备了：

- **训练数据现成**：`data/train_typos.jsonl`（2 万句错句 + 金标标注）。
  模型输入错句、目标输出每字 KEEP/REPLACE(+新字)，即「每字三分类 + 替换字表」的
  一个小 encoder（如 2 层 Transformer / BiLSTM，2~4MB 量化）。
- **评测零改动**：模型输出转成 `{"predictions": [{"position", "correct"}]}` 直接喂
  `eval.py`；与基线同一口径、同一分桶，包括在干净句上的误报率。
- **守卫思路直接复用**：P1 粤语守卫（`src/ipinyin/yue_guard.py`）的哲学是
  「替换要么有实证（词表/短语表/对齐语料里反复出现），要么否掉回退」。
  编辑式模型的每次 REPLACE 同样过这道闸：替换对必须在混淆表/守卫实证表里，
  不在实证表里的改法（学富五车→学不五车这类）整段回退原文——
  正好治上面失败模式 1。本基准的混淆表 `data/confusion.json` 可以直接充当
  守卫的候选白名单种子。
- **算力对照**：统计基线整句约 1ms（纯 dict 查找），编辑式模型目标 3~5ms，
  都在按键路径预算内；真正的分界线是 F1 和误报率，这正是本靶子要量化的。

## 局限

- 底稿语料是聊天式文本，**本身自带少量真实错别字**（如「想者」应为「想着」），
  合成时把它们当作正确原文，指标因此略有噪声；SIGHAN 外部验证可校准。
- 同音按 lexicon 的拼音键判定（无声调、含方言词典映射，如 需/入 同键），
  比严格普通话同音更宽。
- 只覆盖「替换」类错误，不覆盖漏字/多字/语序；P4 假设下这是有意的简化。
- 形近桶占比仅 ~12%（82 个字的覆盖率决定），该桶指标方差较大。


## 混淆集扩展（pycorrector 合并，2026-10-26）

合并 `vendor/pycorrector_data/`（shibing624/pycorrector 的 same_pinyin.txt 3401 字 +
same_stroke.txt 814 字）进混淆表：`merge_confusion.py` → `data/confusion_merged.json`
（同音 8209 字 / 形近 2480 字，较原表 +209/+787 字，候选 +3 万）。

**两个实测发现**：

1. **pycorrector 的表是单向的**：新增同音对里只有 1.2% 带反向映射，而纠错器查
   「错字→候选」——直接合并后分数纹丝不动（考卷 0.019 F1）。同音/形近关系本身
   对称（本仓库自建表从拼音键组挖出，天然双向），合并时补反向是修数据不是造数据。
   对称化后：同表考卷 F1 0.019 → 0.284。
2. **合成考卷量不到扩表价值**：原 test.jsonl 用原混淆表生成，金标纠正在旧表里
   本来可达——合并表在其上持平（0.6367 vs 0.637）是口径限制，不是扩表无用。
   用「只用新增对造错」的考卷（`eval_new_coverage.py`）才量得到：
   召回 0.451→0.521、F1 0.259→0.284，且原 test 无回归。

用法：`baseline.py --confusion data/confusion_merged.json`；新增覆盖口径
`python3 eval_new_coverage.py`。
