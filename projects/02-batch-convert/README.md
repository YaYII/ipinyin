# 项目②：普通话 → 粤语批量转换 CLI（文章 / 字幕）

把输入法引擎（`src/ipinyin/yue.py` 的 `YueConverter` + `yue_guard.py` 的 `YueGuard`
+ 可选的 `yue_nn.py` 神经模型）包成批量工具：整篇文章、SRT/VTT 字幕，逐句
「普通话 → 书面粤语」。引擎原本只服务输入法的 2~8 字短输入，本项目补上批量
场景缺的三块：**转换单位切分**（默认 7 字，见下）、**字幕格式解析/重组**
（时间轴不动）、**逐段统计**（来源 / 守卫修复 / 改动比例）。

核心设计：**转换单位 ≤ 7 字**（= 守卫严格路径阈值 `ctx_max_len`）。长句不一次性
喂给引擎——守卫对 >7 字的输入走宽松路径（只要求输出是语料见过的粤语写法），
句中成语会被静默改坏（`亡羊补牢，为时未晚。` → `亡羊補監`）；切成 ≤7 字的
片段后，**每个片段都过「有实证才改」的严格校验**，这句实测输出 `亡羊補牢`。
切分顺序：终端标点 → 次级标点 → 硬切（`data/lexicon.tsv` 词库护界，不切断
「频道」「想法」这类词语，也不切断英文/数字串）。

## 文件

| 文件 | 内容 |
| --- | --- |
| `convert.py` | CLI + 转换管线 + SRT/VTT 解析/重组 + 保护片段/术语表/QC |
| `sentences.py` | 分句模块（按标点断句、单位上限、词库护界切分），独立可测 |
| `particles.py` | 句尾语气词兜底表（吗→咩/吧→啦/呗→囉） |
| `eval.py` | held-out 评测：照抄/规则/整句36/单位7 四口径分桶打分 |
| `samples/demo.txt` | 10 句日常普通话样例 |
| `samples/demo.srt` | 7 条自拟字幕样例（含双行 cue、`<i>` 标签、疑问语气词） |
| `samples/glossary.tsv` | 术语表样例（保护 番茄；强制 再见→拜拜） |
| `test_convert.py` | pytest：分句、字幕解析/重组、守卫小桩、语气词兜底、保护/术语表、QC、真引擎 parity 与回归、CLI 集成 |

引擎与模型不在此目录：通过 `sys.path` 引 `../../src`，模型在仓库根 `data/`
（`yue.marshal` + `yue.tsv` + `yue_guard.marshal` + `yue_nn.onnx` + `yue_nn_vocab.json`）。
加载方式与 `experiments/exp_yue_guard.py` 一致，守卫语境实证上限同样取 7 字。

## 用法

需要仓库根的 data/ 文件；神经模式还需 onnxruntime（Mac 系统自带 python3 没有，
用隔离环境 `/Users/yingyang/.workbuddy/binaries/python/envs/default/bin/python`）。

```bash
PY=/Users/yingyang/.workbuddy/binaries/python/envs/default/bin/python

$PY projects/02-batch-convert/convert.py 文章.txt                  # 结果写 stdout
$PY projects/02-batch-convert/convert.py 文章.txt --out 译文.txt   # 写文件
$PY projects/02-batch-convert/convert.py 字幕.srt --stats          # 逐段统计（stderr）
$PY projects/02-batch-convert/convert.py 字幕.vtt                  # VTT 同样支持
cat 笔记.txt | $PY projects/02-batch-convert/convert.py -          # stdin 纯文本
$PY projects/02-batch-convert/convert.py 字幕.srt \
    --glossary samples/glossary.tsv --flag 10                      # 术语表 + 可疑片段排序
```

选项：

- `--stats` 向 stderr 输出逐段统计：**来源**（神经 / 神经+修 / 规则）、**守卫**
  （修复次数）、**语**（语气词兜底次数）、**改动**（改动字数比例，按繁体字形
  对齐后统计——繁简字形差异也计入，它衡量「这段被改得多深、要不要人工复核」，
  不是质量分）；
- `--flag N` 可疑片段排序（默认 Top 10）：守卫修复 ×2 + 语气词兜底 ×1 +
  CPS 超标 ×3 + 行宽/时长越界 ×1，输出到 stderr——人工校对从这里看起；
- `--cps` / `--line-width` QC 阈值（默认 9 字/秒、16 全角字符/行，Netflix
  中文 Timed Text 指南口径；0 = 不查）；
- `--glossary FILE` 术语表（TSV：`原词<TAB>指定粤语写法`，译文留空 = 保护不改；
  光秃秃一行也是保护词）。标签（`<i>`、`{\an8}`）、URL、邮箱自动保护；
- `--yue-detect` 片段里粤语专用字 ≥2 个就跳过转换（混语文本防二次转换改坏）；
- `--max-len N` 转换单位上限，默认 7。**调大是质量和安全的交换**：36（物理上限
  38 以内）回到一次性整句转换——口语更流畅、守卫修复少，但句中成语会被静默
  改坏（见「转换质量」）；
- `--no-nn` 纯规则转换（不装 onnxruntime 时自动退到这个模式，并打印提示）；
- `--asis` 不做繁体归一。默认把输出统一成繁体字形：神经输出本是繁体，规则输出
  偏简，混排难看；`data/s2t.marshal` 对粤语专用字（唔識嘅哋喺冇佢……）实测无损。

跑测试与评测：

```bash
$PY -m pytest projects/02-batch-convert/test_convert.py -v   # 36 个用例
$PY projects/02-batch-convert/eval.py                        # held-out 打分（约 2 分钟）
```

| --- | --- |
| 今天天气真好，我们一起去公园走走吧。 | 今日天氣真係好，我哋一齊去公園走走啦。 |
| 妈妈说晚饭已经做好了，叫我快点回家。 | 阿媽講晚飯已經做好喇，叫我快啲返屋企。 |
| 我们先去超市买东西，然后再回家做饭。 | 我們先去超市買嘢，然後再返屋企煮飯。 |
| 你到底想干什么？快说吧！ | 你究竟想做乜嘢？快啲講啦！ |
| 这个问题我不太懂，你能给我讲一下吗？ | 呢個問題我不太懂，你能畀我講一下**咩**？（语气词兜底：守卫拦回后查表补上） |
| 他比你高，跑得也比你快。 | 佢比你高，跑得都比你快。 |
| 太好了，明天不用上班，可以睡懒觉了。 | 太好喇，聽日唔使返工，可以瞓懶覺咗。 |

| 我们不懂他的想法，也没问过他。 | 我哋唔識佢嘅諗法，都冇問過佢。 |

统计汇总：`共 27 段 | 神经 27 / 规则 0 | 守卫修复 12 段 | 语气词兜底 1 处 | 平均改动 31%`。
口语词转得好的正是规则表当年不敢收的：不懂→唔識、明天→聽日、不用→唔使、
在→喺度。旧引擎的两个切片事故（走走吧→行走啦、家常菜→屋企常菜）已被
「真词增广 + 8 轮」版模型治好。

`convert.py samples/demo.srt --glossary samples/glossary.tsv`（时间轴/序号原样，
只有文本行被替换；标签/术语保护、语气词兜底都在真实字幕上生效）：

切三個番茄，唔使切太細。        ← 番茄 受术语表保护，原样保留

00:00:19,000 --> 00:00:22,000

`--flag 5` 会把守卫动过的 cue 和 行宽>16 的 cue 排到最前面，人工校对从上往下看。

## 转换质量（`eval.py`，held-out 实测 2026-10-26）

引擎版本：神经 =「真词增广 + 8 轮」版 ONNX（2026-10-26 重导出，源权重
`experiments/yue_model_d256.pt`）+ 守卫语域先验三件套（简繁外壳免实证、
典籍白名单、见 `docs/nn-upgrade.md`）。正确判据与 `experiments/exp_yue_guard.py`
相同（t2s 归一后逐字比对、同一 seed=0 切分；v1.3 判分含合法变体），四口径同台：

| 桶 | n | 照抄 | 规则 | 整句36 | 单位7 | 守卫修复(单位7) |
| --- | --- | --- | --- | --- | --- | --- |
| 2字词（真词口径） | 25 | 0.0% | 36.0% | 96.0% | **96.0%** | 0 |
| 4字成语（答案=不改） | 40 | 100% | 97.5% | **100.0%** | **100.0%** | 8 |
| 5-7字口语 | 300 | 16.3% | 32.3% | **42.0%** | **42.0%** | 105 |
| 5-7字古诗（答案=不改） | 12 | 100% | 75.0% | **100.0%** | **100.0%** | 6 |
| 8-15字句子 | 300 | 2.0% | 17.7% | **46.7%** | 39.3% | 139 |

（2字桶 2026-10-26 起被真词过滤重定义——旧口径 265 题含跨界碎片有水分，
净化后 25 题全真词，与旧数字不可纵向比。）三个结论：

1. **≤7 字的桶上 单位7 与 整句36 一致或几乎一致**；成语/古诗守卫后 **100%**
   （典籍白名单：白名单输入直接给繁体外壳，`亡羊補牢` 不再可能变 `補監`）；
2. **切分的代价全部落在长句**：8-15字 46.7% → 39.3%（−7.4pt，模型缺上下文 +
   片段边缘缺语境实证；语气词兜底已回收一部分）。但仍比规则高 22pt，且没有
   静默改坏——**安全换流畅，默认值如此**，`--max-len 36` 可换回来；
3. **守卫修复是双刃剑**：修复段里成语/古诗类是救回，也有 帶遮→帶傘 这类弄丢。
   `--flag` 的排序就是人工复核的优先级。

延迟（M2 Pro，ONNX int8，含分句、t2s 与守卫）：2字词 8ms/句、5-7字
19ms/句、8-15字 37ms/句（多段推理）——千句文章约半分钟，可接受。

## 局限

1. **片段边缘的合法口语转换会被严格守卫挡掉**。语境实证看邻字搭配，而切分
   恰好把邻字切走：`記得帶傘。` 单独成段时神经给的 `帶遮`（遮=伞，正确粤语）
   被修回 `帶傘`（demo 第 8 行实录）。句尾语气词（吗→咩/吧→啦/呗→囉）已有
   兜底表回收，词汇级的要靠术语表或守卫实证表扩充。
2. **无标点长子句切成片段后，模型对孤立片段的理解弱于整句**：8-15字桶
   39.3% vs 整句 46.7%（−7.4pt）就是这项成本。旧引擎的两个切片事故
   （`走走吧`→`行走啦`、`家常菜`→`屋企常菜`）已被「真词增广+8轮」模型治好，
   但结构性成本仍在——词库护界只保证**切在词边界**，不保证语义完整。
3. **跨片段的语序重排会被拦**：`我们先去超市` → 神经给 `我哋去超市先`
   （正确的粤语语序），但重排缺片段级实证，被回退成 `我們先去超市`。
4. **字幕/文章仍需人工校对**：5-7 字口径的神经+守卫 ≈ 42.0%，离「直接可用」
   有距离；粤语书面写法本身有多地差异（本引擎倾向香港口语用字）。`--flag`
   负责告诉你先看哪几条，不负责替你看。
5. **简繁归一靠 s2t 词表**：多音多义字（只/乾/后 一类）按词表选字形，可能
   选错；不放心就用 `--asis` 原样输出（会简繁混排）。
6. **纯文本逐行处理**：不跨行合并断句，硬换行的散文会按行拆散句子。
7. **兜底与 QC 都是保守的粗校准**：语气词表只收 3 对基本无歧义映射（宁可少
   收，更多映射走 `--glossary`）；CPS/行宽阈值取 Netflix 中文指南当量
   （9 字/秒、16 字/行），没有按节目类型细分。

## 下一步

2026-10-25 已落地：`--flag` 可疑片段排序（守卫 + 语气词 + CPS/行宽/时长 QC）、
`--glossary` 术语表（保护/强制 + 标签/URL/邮箱自动保护）、句尾语气词兜底表、
`--yue-detect` 已是粤语跳过。以下按 GitHub 调研（同类项目 + GECToR /
COMET-QE 先例）排的优先级：

1. **回译一致性打分**：用项目①的 yue→zh 反向模型把输出翻回普通话与原文比对，
   做参考无关的质量分（COMET-QE 思路的本地轻量版）喂给 `--flag`——两个基线
   项目联动，零额外训练（① 已有抗错字版模型，噪声译文也能扛）；
2. **大语料重训——部分已落地**（2026-10-26：「真词增广+8轮」晋升生产并重导出
   ONNX，8-15字 44.3→46.7）。下一档：raptorkwok 13 万对 + hon9kon9ize 38k
   （许可证待验证）再翻倍；重训后重切 held-out 防泄漏；
3. **CanCLID 词库四件套**（rime-cantonese-upstream，CC-BY/ODbL）：
   `fixed_expressions.csv` 喂守卫做成语白名单、`variant.csv` 补 s2t 多义字
   选形、`word.csv` 升级护界词表；
4. **更聪明的切分**：短片段与相邻片段在 ≤7 约束内合并尝试；「不太/已经」
   类双字副词切分回避；
5. **编辑式模型**（对应 nn-upgrade §四 P4，GECToR/FCGEC 已印证该范式）：
   token 级「保留/替换」标注 + 逐 token 置信度天然可得，根治局限 1-3。
