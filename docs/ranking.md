# 候选排序：一个分数决定一切

所有候选（字、词、表情、学过的词）都进同一个打分函数，按分数从高到低排。
想调整手感，只改这里的系数即可，不用动排序逻辑。

```
score(候选) = 词频
            + 选中次数 × 800,000
            + 命中率   × 200,000
            + 上下文命中 × 400,000
            + 150,000        # 整串匹配（音节数 = 字数，且 ≥2 音节）
            × 0.02           # 只匹配部分音节的单字（压到后面）
```

| 项 | 来源 | 作用 |
| --- | --- | --- |
| 词频 | 词库（`data/lexicon.tsv`） | 通用先验；人工收录的现代词标 1e9（微信/支付宝…） |
| 选中次数 | `user_model.tsv` 的 picks | 你的习惯，选一次就压过常见词 |
| 命中率 | picks / 展示次数 | 经常一次就中，说明偏好稳定 |
| 上下文 | `user_bigram.tsv` | 打完「因为」，“所以”提前 |
| 整串匹配 | 候选字数 = 音节数 | 防止「哈哈」被单字「哈」抢走 |
| 部分匹配罚 | 单字只用了一部分拼音 | `diyiye` 里的「页」不会顶掉「第一页」 |

## 表情为什么不再钉在第一

表情也是候选，初始 0 分（没词频、没选过），所以排在文字候选之后；
你选它一次 → +800,000 → 下次第一；之后总选「哈哈」→「哈哈」分数涨回来又超过它。
**选过的升，不选的沉**，和文字完全同一套机制。

## 调参方式（改一个数就行）

- 想让「选过」影响更猛烈：调大 `PICKS_BONUS`（`src/ipinyin/ime.py`）
- 想让表情更容易出现：给 emoji 候选一个初始分（现在是 0）
- 想让长词更占优：调大整串匹配的 150,000
